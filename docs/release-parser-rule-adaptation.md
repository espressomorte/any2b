# Порівняння Rust-порту та план адаптації до Kotlin

Перевірено саме [g0ldyy/torrent-parse-rank](https://github.com/g0ldyy/torrent-parse-rank/tree/e21b3e77987c4a51c8168d9d59de9a718a48c990), версію пакета 0.1.0, commit `e21b3e77987c4a51c8168d9d59de9a718a48c990`. Це запуск зібраного Rust-розширення через Python API, а не upstream Python PTT. Вхід — ті самі 20 незмінених заголовків Toloka з попереднього аудиту.

Сирі відповіді обох API, версії залежностей, SHA-256 вибірки й перевірки кожного поля: [JSON](torrent-parse-rank-audit.json). Таблиці результатів: [звіт](torrent-parse-rank-audit.md). Попередній [Kotlin baseline](release-parser-toloka-random-20.md) залишається без змін.

## Що показав запуск

| Поле | Kotlin | Rust-порт PTT / RTN |
| --- | --- | --- |
| Рік | 20/20 | 20/20 |
| Джерело за поточними категоріями Kotlin | 17/20 | 18/20 |
| Роздільність | 18/20 | 20/20 |
| Кодек | 20/20 | 20/20 |
| Усі назви-кандидати | 4/20 | 0/20: API повертає одну назву |

Rust-порт повернув одну назву, яка точно збігається з одним очікуваним alias, у 13/20 випадків. У решті семи в назві залишилися українські позначки сезону/серій. Обидва API дали однакові значення вимірюваних полів.

Номери сезонів/епізодів правильні у 19/20 випадків; total бібліотека не повертає. У «Монолог травниці» правильно знайдений сезон 3, але не серії з лічильника `08 з 12`. Ця метрика слабша за перевірку типізованого покриття Kotlin, тому напряму порівнювати 19/20 з його 13/20 не слід.

У всіх 20 результатах languages містить зайвий `ru`. У двох заголовках із `2xUkr`/`3xUkr` також пропущено `uk`. У Pentathlon `fr` додається через примітку про трансфер. У Rammstein `uk` у загальному списку стосується субтитрів, тоді як аудіо — `de`. Відокремити ці ролі з одного languages неможливо. Ще один хибний факт: `mono` у каналах заголовка Ojisan wa Kawaii Mono ga Osuki, хоча це слово назви.

Повні 4/20 Kotlin оцінювали весь контракт одночасно, включно з альтернативними назвами й окремими мовами. Порівнянного повного відсотка для API Rust-порту немає. Вимірювання швидкості на 20 рядках не проводилося.

## Які правила адаптувати

Джерело для аналізу — `crates/ptt-core/src/generated/handlers.json` та механізм виконання в `crates/ptt-core/src/lib.rs` у зафіксованій ревізії.

1. **Роздільність.** Перенести покриття interlaced/progressive, зокрема 576i; зберегти межі токенів, контекст і evidence. Не замінювати i на p. Наші тести повинні перевіряти обидва типи.
2. **Джерела.** Додати DVDRemux та WEB-DLRip/WEBDLRip як явні категорії. Rust-порт згортає DVDRemux до DVD — це втрата специфічності, яку повторювати не потрібно. BluRay та remux надалі варто моделювати окремими фактами.
3. **HDR та редакції.** Запозичити покриття HDR/DV і Theatrical, додати власні поля та правила технічного суфікса. Визначати примітку `[FRA Transfer]` як примітку про джерело, не мову аудіо. Невідомі дужки з назви не видаляти.
4. **Сезони й серії.** Використати приклади й порядок спеціалізованих обробників як основу тестів. Український блок розбирати цілком: сезон + серії + total або unknown. Наявність англійського Season 1 в іншому alias не повинна створювати конфлікт із тим самим сезоном. Лічильник `08 з 12` потребує нашого правила джерела з позначеним припущенням.
5. **Контроль обробників.** Розділити пошук фактів, видалення з області назви й пріоритет правил. Значення на зразок skipIfAlreadyFound не копіювати механічно: наш контракт має виявляти суперечності, а не мовчки залишати перший збіг.

Не переносити правило «кирилиця → ru», змішування мов, видалення альтернативних назв і розпізнавання технічних слів без контексту. Ці помилки підтверджені саме нашою вибіркою. Для мов потрібні окремі контексти audio/subtitles і необов'язковий префікс кількості доріжок. Кількість доріжок не повинна губитися після нормалізації мови.

Ліцензія Rust-порту — GPL-3.0-or-later (pyproject.toml). Код і таблиці правил у Kotlin у межах цього порівняння не копіювалися. Для прямого перенесення потрібно зафіксувати походження/ліцензію вибраних правил та сумісність із поширенням any2b. Наразі результат — зовнішній benchmark і план адаптації, без нової runtime-залежності застосунку.

## Відтворення

Потрібні Python 3.12, Rust toolchain і окремий venv. Checkout та venv можна розмістити у тимчасовій теці. Не встановлювати Python/Rust у runtime Android.

```sh
git clone https://github.com/g0ldyy/torrent-parse-rank.git /tmp/any2b-tpr
git -C /tmp/any2b-tpr checkout e21b3e77987c4a51c8168d9d59de9a718a48c990
python3.12 -m venv /tmp/any2b-tpr-venv
/tmp/any2b-tpr-venv/bin/pip install /tmp/any2b-tpr
/tmp/any2b-tpr-venv/bin/python release-intelligence/tools/compare_torrent_parse_rank.py --checkout /tmp/any2b-tpr --output docs/torrent-parse-rank-audit
```

Точні версії використаних залежностей записані в JSON-звіті; для дослівного відтворення зафіксувати також ці версії під час встановлення. Скрипт лише нормалізує еквівалентні позначення виходу й порівнює з ручними очікуваннями. Він не чистить заголовки перед викликом бібліотеки та не додає відсутні дані.

Наступна реалізація: спочатку цілісний локалізований блок серій і межа технічного суфікса, потім джерела/роздільність/HDR та мовні контексти. Після кожного кроку запускати незмінену вибірку Toloka й 20 назв AniTube, переглядати knownGaps. Показники з цієї вибірки не є оцінкою всього трекера.
